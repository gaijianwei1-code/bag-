## 冒烟抓出的真 bug
`FAIL: run_id 为空应报 error 而非静默`
根因：`m_state` 只在 dock 的 `stateChanged` 回调里赋值 → **没有 dock 时状态读不到**。
修复：所有 `emit stateChanged(...)` 之前先给 `m_state` 赋值（6 处）。
这是"状态机状态依赖 UI 存在"的设计缺陷，不是测试问题。

### 联调抓出的真 bug（adapter 空参数）
```
FileNotFoundError: [Errno 2] No such file or directory: ''
```
`b_line_run.py` 第 6 个参数是 adapter 路径，传空字符串会直接 `open('')` 报错，
**不像第 5 个参数那样能省略**。
根因：我加 `ps_dir`（第 5 参数）时保留了末尾的 `''`，于是 adapter 变成了真正的空参数。
修复：命令改为 `... {cpath} {ps_dir}`（省略 adapter，用默认值）。

**UI 表现**：run 在 0 秒变 failed，用户点「连接」会看到"什么都没发生"，无法排查。
这就是端到端联调的价值——单测和冒烟都不会碰这条路径。

run_record 有 `schema/line/run_id/started_at/ended_at/duration_s/scene/param_set/param_plan/...`，
但 F 门指标（tracking_rms 等）不在顶层，需要进一步定位实际字段路径。
