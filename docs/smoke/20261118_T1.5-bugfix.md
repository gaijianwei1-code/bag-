# T1.5 bugfix 冒烟 — PASS（2026-11-18，用户实测报障后修复）

## 用户报障（真实使用）
1. 添加 `1793346971223_frames_no_ground.pcd` 后**地图工具没有任何显示效果**
2. 点击"前视快算" → **闪退**

## 根因（两个都是集成层真 bug，core 逻辑已独立验证无误）
| # | Bug | 机制 |
|---|---|---|
| 1 | **闪退：悬垂指针** | `pgmScene->clear()`（打开新图走 cleanImage）会 delete 场景内所有 item，包括前视 overlay。`FovLayer` 仍持裸指针 `m_overlay`，`rebuildOverlay()` 见指针非空就跳过重建 → `setEntries()` 写已释放内存 → SIGSEGV |
| 2 | **无显示：被地图盖住** | overlay `setZValue(-1.0)`，而地图 pixmap 的 z 默认 0 → 扇形/红点全画在地图图片**底下**，肉眼完全不可见 |

## 修复
- `FovOverlayItem` 改继承 `QGraphicsObject`（QObject+QGraphicsItem），用 `QPointer<FovOverlayItem> m_overlayGuard` 守卫：场景析构时自动置空，`rebuildOverlay()` 以 guard 判空 → 必重建；`destroyOverlay()` 也走 guard，不再对已删对象 removeItem/delete
- `setZValue(-1.0)` → **`0.5`**：高于地图（0）、低于工具栏/选区（1000），且本 item 不接受鼠标事件故不影响轨迹拖拽
- `recalcAll()` 加防御：`path->scene() != m_scene` 的轨迹跳过（场景 clear 后 m_path_list 里的 BPathItem 也已悬垂）
- `cleanImage()` 在 `pgmScene->clear()` 之后补 `fovLayer->setPathList({})`，先清悬垂轨迹指针再让图层重建

## 崩溃定位方法（可复用）
Mac 上 `~/Library/Logs/DiagnosticReports/test_*.ips` 的 threads[0].frames + 符号化，直接指出崩溃在 `QGraphicsItem::zValue()` 被调用于已析构对象——比 lldb 在无头环境更省事。

## 教训（写进规范）
1. **集成层冒烟必须覆盖"场景重入"**：clear/rebuild 是 Qt GraphicsView 最容易漏的生命周期点；子代理的 11 断言只测了单次开关，没测 clear 后重开
2. **z 值语义要写出参照系**：不能只说"压在轨迹之下"，必须明确"高于地图、低于工具栏"，否则换个地图就看不见
3. 用户实测是最有效的验收——两个 bug 自动化全过了却被肉眼一秒发现
